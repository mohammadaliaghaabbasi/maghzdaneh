## مرحله ۱ — استراتژی و مدیریت ✅

**بریف:** فروشگاه تخصصی مغز — نه آجیل‌فروشی عمومی. سه ستون کسب‌وکار:
1. **خرده‌فروشی** (مصرف خانگی، از ۲۵۰ گرم)
2. **عمده‌فروشی** (قنادی، آجیل‌فروشی، سوپرمارکت، رستوران، صنایع غذایی — تا ۲۵ کیلو+)
3. **خرید از مبدأ** (باغدار و بنه‌دار محصول می‌فروشد — صفحه عرضه)

**تمایز اصلی:** قیمت پلکانی شفاف (نه «تماس بگیرید»)، تمرکز روی مغز پسته در همه گریدها، و پوشش کل زنجیره از دست اول تا مصرف‌کننده.

**KPI:** نرخ تبدیل کاتالوگ→سبد، میانگین ارزش سبد، درصد سفارش‌های نیم‌عمده/عمده.

**MVP:** ویترین + سبد + تسویه + پنل مدیریت + عرضه. خارج از MVP: درگاه پرداخت واقعی، حساب کاربری، ردیابی سفارش.

**استک:** استاتیک خالص (HTML/CSS/JS) + GitHub Pages + GitHub Contents API به‌عنوان دیتابیس نوشتاری. دلیل: هزینه صفر، سرعت بالا، و دیتابیس کاملاً شفاف (هر تغییری کامیت است).

## مرحله ۲ — تحقیق کاربر ✅

**پرسوناهای اصلی (مبتنی بر رفتار واقعی بازار مغز):**

| پرسونا | درد اصلی | کاری که برایش ساختیم |
|---|---|---|
| **مینا، ۳۴ ساله، تهران** — مصرف خانگی | نمی‌داند کدام مغز برای چی مناسب است؛ می‌ترسد مغز مانده بگیرد | جدول «کدام مغز پسته برای شما؟»، بج تازه‌برشته، حداقل خرید ۲۵۰ گرم |
| **استاد کریمی، ۵۱ ساله** — قنادی | قیمت عمده مبهم است؛ خلال تقلبی دیده | قیمت پلکانی شفاف روی جدول کامل، مشخصات فنی خلال (درجه A، بدون خاکه)، صورت‌حساب رسمی |

**جریان‌های کلیدی:** مرور→محصول→سبد→تسویه (خریدار)، ویرایش قیمت→کامیت (ادمین)، پیشنهاد عرضه→تماس کارشناس (باغدار).

## مرحله ۳ — برندینگ ✅

- **نام: مغزدانه** (مغز + دانه) — کوتاه، فارسی، دقیقاً حوزه تخصص را می‌گوید: «مغز» قلب کسب‌وکار و «دانه» یادآور خشکبار.
- **لوگو:** SVG دست‌ساز — دانه مغز پسته دو‌پاره با شیار، در دایره کرم. واریانت مونوکروم + فاوآیکون.
- **پالت:** سبز پسته `#2f7d4f` (اصلی) · سبز تیره `#1f5c39` · طلایی زعفرانی `#b8860b` (اکشن/تخفیف) · کرم `#faf8f3` (پس‌زمینه) · سبز تیره `#14261c` (فوتر/عرضه).
- **تایپوگرافی:** وزیرمتن — ۴ وزن (Regular/Medium/Bold/Black) به‌صورت محلی (بدون CDN، برای کاربر ایرانی).
- **لحن:** صمیمی-متخصص؛ اصطلاح بازار (نس، پرخوری، نوک‌زنی، خورشتی) با توضیح کوتاه در پرانتز.

## مرحله ۴ — طراحی UX ✅

- وایرفریم همه ۱۲ صفحه به‌صورت متنی، سپس پیاده‌سازی مستقیم (پروژه تک‌نفره با AI).
- **تسویه ۳ مرحله‌ای** طبق ورک‌فلو: اطلاعات خریدار → آدرس ارسال → روش پرداخت (تا ۴ مرحله نرسید).
- حالت‌های خاص: سبد خالی، سفارش آفلاین (fallback)، محصول ناموجود، ۴۰۴.
- دسترس‌پذیری: ناوبری با کیبورد، aria-label فارسی روی همه دکمه‌های آیکونی، کنتراست AA.

## مرحله ۵ — طراحی UI ✅

دیزاین سیستم در `assets/css/main.css` با توکن‌های CSS: پالت، مقیاس تایپ fluide با `clamp()`، شعاع‌ها، سایه‌ها. کامپوننت‌ها: دکمه (۴ گونه)، کارت محصول، چیپ فیلتر، انتخاب پله، فرم، جدول، مودال، توست، حالت خالی، آکاردئون FAQ. همه حالت‌ها (هاور/ فوکوس/ فعال) پوشش داده شده. موشن محدود به transition کوتاه (0.15–0.2s) — حس بازار سنتی، نه SaaS.

## مرحله ۶ — تولید محتوا ✅

- **صفر لورم‌ایپسوم.** هر ۲۰ محصول: نام + مبدأ واقعی (رفسنجان، دامغان، تویسرکان…) + گرید + توضیح تخصصی + مشخصات + کاربردها.
- محتوای تخصصی واقعی: توضیح «انس یعنی چه»، فرق سبز و سرخ، چرا فندقی اقتصادی‌تر است، فرق گردوی خورشتی و لوکس.
- ۸ سوال متداول از درد واقعی خریداران مغز + ۳ نظر مشتری (قنادی، سوپرمارکت، خانم).

## مرحله ۹ — دیتابیس ✅ (قبل از ۸ طبق وابستگی ورک‌فلو)

`data/db.json`: ۲۰ محصول × قیمت ۳ پله، ۵ دسته، تنظیمات سایت/ارسال/پرداخت، FAQ، نظرات، عرضه. طراحی برای نوشتن با Contents API (کامیت = تغییر). سفارش‌ها در `data/orders/YYYY-MM/MD-*.json` — ماهانه پارتیشن‌بندی شده.

## مرحله ۸ — بک‌اند (GitHub به‌عنوان سرویس) ✅

- **قرارداد خواندن:** GET خام `data/db.json` از Pages — بدون توکن، با cache-bust.
- **قرارداد نوشتن:** PUT `contents/data/db.json` و PUT `contents/data/orders/...` با کامیت‌مسیج فارسی معنادار. SHA برای آپدیت خوانده و ارسال می‌شود (بدون overwrite کورکورانه).
- `assets/js/ghdb.js`: لایه API واحد — fetchDB / saveDB / submitOrder / listOrders / readOrder / checkAuth. توکن فقط از localStorage خوانده می‌شود، هرگز هاردکد نیست.

## مرحله ۷ — فرانت‌اند ✅

- ۱۲ صفحه عمومی + پنل ادمین، همه RTL کامل، واکنش‌گرا در ۳ بریک‌پوینت (۱۲۸۰ / ۸۲۰ / ۶۴۰ و ۳۷۵px موبایل).
- قیمت‌ها زنده از db.json؛ تغییر پله خرید، کل سایت را به‌روز می‌کند (event-driven با `tier:changed`).
- اعداد فارسی (`toLocaleString('fa-IR')`) همه‌جا.
- تست‌شده با مرورگر هدلس: ۱۱ صفحه بدون خطای کنسول، جریان خرید سرتاسری (محصول→سبد→فرم→ثبت→صفحه موفقیت با کد پیگیری) تأیید شد.

## مرحله ۱۰ — فروشگاهی ✅

- کاتالوگ با فیلتر/جستجو/مرتب‌سازی؛ سبد با ویرایش مقدار؛ جمع زنده؛ منطق ارسال رایگان بالای سقف؛ هشدار بار سنگین بالای ۱۰ کیلو.
- قیمت پلکانی در سه‌جا: صفحه محصول (انتخاب + محاسبه زنده)، جدول wholesale، کارت‌های کاتالوگ (قیمت بر اساس پله فعال).
- سفارش با ساختار کامل (آیتم×پله×وزن×جمع) + وضعیت (new/processing/done/canceled).

## مرحله ۱۱ — امنیت ✅

- توکن هرگز در کد نیست؛ فقط localStorage مرورگر ادمین + هدر Authorization در همان درخواست.
- توصیه شده توکن fine-grained فقط با دسترسی Contents::RW روی همین ریپو ساخته شود.
- admin/checkout/cart/success با robots.txt و متا noindex از اندیس شدن خارج‌اند.
- سبد و پیام‌ها فقط localStorage — بدون کوکی ردیاب. اعتبارسنجی سمت کلاینت + اعتبارسنجی JSON قبل از کامیت.
- ⚠️ مورد شناخته‌شده: سایت استاتیک است و نوشتن نیازمند توکن است؛ برای تیم چندنفره، هر ادمین توکن شخصی خودش را وارد می‌کند (audit trail = تاریخچه کامیت‌ها).

## مرحله ۱۲ — تست و QA ✅

- مرورگر هدلس (agent-browser/Chromium): همه صفحات لود، صفر خطای کنسول.
- جریان خرید E2E دستی: انتخاب پله → مقدار → افزودن → سبد (جمع صحیح ۸٬۵۰۰٬۰۰۰) → فرم → ثبت → success + کد پیگیری.
- تست موبایل ۳۷۵px: اسکرین‌شات، بدون سرریز افقی (grid های auto-fill با min()).
- تست fallback آفلاین: سفارش محلی ذخیره و پیام راهنما نمایش داده شد.

## مرحله ۱۳ — DevOps ✅

- میزبانی GitHub Pages از برنچ main — استقرار = push. HTTPS خودکار.
- هر تغییر ادمین یک کامیت است: rollback = revert کامیت. تاریخچه کامل تغییرات قیمت = git log.
- بدون build step — بدون pipeline شکننده.

## 🔁 فاز ۲ — ارتقای سه‌بعدی (آبان ۱۴۰۵)

درخواست کارفرما: نسخه‌ای بسیار گرافیکی‌تر با الهام از سایت‌های سه‌بعدی برتر که در گفتگو معرفی شده بودند. از میان منابع (`inspiration_data.json` ریپوی مرجع + گفتگوی پروژه)، بر اساس معیار «بهترین نمونه 3D تعاملی»، **Lusion** (برنده Awwwards، سبک‌ساز WebGL استوری‌تلینگ) به‌عنوان مرجع اصلی و **Codrops** (شیدر grain، کروسل پارچه‌ای) و **GSAP Showcase** به‌عنوان مکمل انتخاب شدند و زبان طراحی استخراج شد:

| الگوی برداشته‌شده | پیاده‌سازی در مغزدانه |
|---|---|
| WebGL تمام‌صفحه با موضوع واحد | `scene3d.js` — مغز پسته سه‌بعدی رویه‌ای (LatheGeometry) با دو نیمه که با اسکرول از هم باز می‌شوند |
| شیدر دانه‌دار تیره (Propagande/Codrops) | پس‌زمینه fullscreen-quad با نویز FBM + وینیت + گرین |
| HUD استودیویی (شمارنده‌ها/قاب‌ها در Lusion) | قاب چهارگوشه هیرو، بج عمودی EST. 2026، حلقه‌های مداری سه‌بعدی |
| اسکرول‌روایت پیوسته | سکشن «زنجیره» — سفر دانه از بنه تا سفره |
| تایپوگرافی قهرمان درشت با درخشش | `hero-title-3d` با نئون سبز و طلایی |
| dolly دوربین با اسکرول + واکنش به موس | camera.z و lookAt وابسته به scrollT و pointer |
| حرکت با فیزیک نرم (lerp) | موس/کرسر/پارالاکس همه با easing نرم |

**فایل‌های جدید:** `assets/js/scene3d.js` (صحنه)، `assets/js/motion.js` (reveal/parallax/tilt/magnetic/marquee/counter/progress/cursor)، `assets/css/fx.css` (لایه بصری تیره)، `assets/js/three.module.js` (Three.js r160 محلی — بدون CDN).

**دسترس‌پذیری و پایداری:** fallback خودکار CSS برای نبود WebGL؛ احترام کامل به `prefers-reduced-motion`؛ توقف رندر در تب مخفی؛ pixelRatio محدود در موبایل؛ حجم Three.js gzip‌شده ~170KB و فقط در صفحه اصلی لود می‌شود.

**تست فاز ۲:** همه ۱۰ صفحه بدون خطای کنسول؛ موبایل ۳۷۵px بدون سرریز افقی؛ صحنه در دسکتاپ و موبایل رندر و به اسکرول واکنش نشان داد (تحلیل پیکسلی اسکرین‌شات: ~۱۱٪ سبز صحنه در دسکتاپ، ~۱۸٪ موبایل، زمینه تیره ~۶۶٪).

### ۲. ارتقای صحنه سه‌بعدی استودیویی (`assets/js/scene3d.js`)

## 🔁 فاز ۴ — بازطراحی سه‌بعدی اسکاپت‌شده (کیفیت استودیویی Blender/PBR) و رفع کامل باگ‌های همپوشانی

در پاسخ به بازخورد مستقیم درباره کیفیت گرافیکی پسته سه‌بعدی قبلی و باگ‌های همپوشانی صفحات، معماری سه‌بعدی و چیدمان کل سایت با الهام مستقیم از منابع منتخب `data/inspiration_data.json` ریپوی مرجع (**Lusion**، **Awwwards**، **Spline**، **Codrops**، **Theatre.js**، **GSAP Showcase**، **Godly** و **Aceternity UI**) بازطراحی کامل شد:

### ۱. مدل سه‌بعدی اسکاپت‌شده و شیدینگ PBR استودیویی (`assets/js/pistachio-model.js` و `assets/js/scene3d.js`)
- **پسته خندان واقعی با هندسه بسته و ضخیم (`buildSolidShellValveGeometry`):** دو نیمه‌پوست قایقی استخوانی با ضخامت واقعی، لبه پخ‌دار چهارمرحله‌ای، حفره داخلی صدفی-براق و لولای طبیعی در پایه (پسته هنگام باز شدن از پایه خندان می‌شود، نه به‌شکل دو پرانتز شناور).
- **مغز پسته اسکاپت‌شده آناتومیک (`buildSculptedKernelGeometry`):** مش با تفکیک‌پذیری بالا (`68 × 54`) با انحنای طبیعی دوقسمتی (شیار شکمی لپه‌ها، قوس پشتی و برآمدگی ارگانیک با نویز چنداکتاوی) بدون هیچ کره یا مخروط چسبیده‌ای.
- **نقشه‌های PBR ۵۱۲×۵۱۲ رویه‌ای (Albedo + Sobel Tangent-Space Normal + Roughness):** تولید بافت طبیعی پوست نازک ارغوانی-بنفش مات (`roughness ≈ 0.72`) در تضاد با گوشت سبز زمردی نیمه‌چرب (`roughness ≈ 0.28–0.38`) و بافت چوبی-الیافی پوسته برای ۴ رقم: **اکبری ممتاز، کله‌قوچی، فندقی و برشته زعفرانی**.
- **نورپردازی استودیویی Cycles-Style:** محیط بازتاب چندسافت‌باکسه (`PMREMGenerator`)، نور کلیدی زعفرانی با سایه نرم (`PCFSoftShadowMap` با نگاشت ۱۰۲۴×۱۰۲۴)، نور حاشیه‌ای زمردی، بازتاب گرم کف استودیو، ذرات بوکه دایره‌ای نرم (`createSoftBokehTexture` بدون پیکسل مربعی) و ۶ مغز/خلال مداری شناور.
- **مدیریت عملکرد و WebGL:** توقف خودکار هر صحنه خارج از دید با `IntersectionObserver` (حداکثر یک بوم WebGL فعال در هر لحظه)، پشتیبانی `ResizeObserver`، بازیابی `webglcontextlost`/`restored` و همگام‌سازی `fenceSync` در رندر نرم‌افزاری.

### ۲. چیدمان هیرو بدون همپوشانی و روایت اسکرولی سه‌بعدی (`index.html` و `assets/css/fx.css`)
- **هیرو دوسطونی صفر-همپوشانی (`.hero-grid`):** ستون راست مخصوص تیتر، توضیح، فراخوان‌ها و آمار؛ ستون چپ اختصاصی برای صحنه سه‌بعدی تمام‌نما (`.stage-viewport`) با کنسول تعاملی یکپارچه دقیقاً زیر بوم (انتخاب ۴ رقم، اسلایدر میزان خندانی ۰ تا ۱۰۰٪، ۳ زاویه دوربین `کامل` / `کلوزآپ مغز` / `نمای بالا` و دکمه `ریست`). در موبایل صحنه سه‌بعدی بدون تداخل بالای متن قرار می‌گیرد.
- **نمایشگاه سه‌بعدی چسبنده ۳ فصلی (`.story3d`):** الهام‌گرفته از الگوی روایت اسکرولی Lusion/GSAP/Theatre.js؛ با اسکرول یا کلیک روی ۳ فصل («پوست خندان»، «مغز زمردی»، «برشته‌کاری روز»)، دوربین و زاویه باز شدن پسته به‌صورت زنده و پیوسته کارگردانی می‌شود.
- **افکت نور موضعی تعقیب‌کننده نشانگر (`.card`, `.cat-tile`, `.chain-node`, `.tier-card`):** پیاده‌سازی سبک GPU-only با یک لیسنر واحد در `motion.js` و احترام کامل به `prefers-reduced-motion`.
